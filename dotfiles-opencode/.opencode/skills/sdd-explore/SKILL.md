# SDD Explore Skill

## Objective

Explore problem space, constraints, and repository impact before proposing a change.

## Workflow

1. Read relevant docs and implementation hotspots.
2. Identify business goal, scope boundaries, and non-goals.
3. Capture assumptions and open questions.
4. Produce a concise exploration report.

## Output Format

- `status`
- `executive_summary`
- `current_state`: how system works today
- `gaps`: what is missing
- `constraints`: technical/organizational limits
- `options`: 2-3 approaches with tradeoffs
- `next_recommended`
- `risks`

## Guardrails

- Validate claims with code/doc evidence.
- Keep scope tightly aligned with user request.
- Do not write production code in explore phase.
